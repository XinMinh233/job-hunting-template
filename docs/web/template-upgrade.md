# 模板升级

模板源版本由仓库根目录的 `TEMPLATE_VERSION` 标记。Runner 在开通用户时记录版本和逐文件 SHA-256 清单。

## 新用户

新用户始终复制当前模板白名单。Web 源码、部署文件和模板源 `.git` 不会进入用户 workspace；workspace 会重新 `git init` 并产生独立初始提交。

## 旧用户

只在管理员点击“升级模板”时升级。流程：

1. Runner 确认用户 Git 工作区干净；有未提交改动就整体停止。
2. 对每个受管文件比较“开通/上次升级时哈希”和“当前用户文件哈希”。
3. 未被用户修改的受管文件替换为新版。
4. 被用户修改的受管文件跳过并进入冲突报告。
5. 报告写入 `data/template-upgrade-reports/`，与成功更新的文件一起由用户 UID 自动提交。
6. registry 和业务数据库记录新版本。

## 永不自动覆盖

- `master.md`
- `CLAUDE.md`
- `base/`
- `data/`
- `tailored/`
- `uploads/`
- `dist/`
- 用户 Git 历史

上述文件即使模板源变化也只记录为保留项。需要迁移个人数据时，应先备份，再以用户可见 diff 人工处理。

## 发布新版模板

1. 在模板源中修改工作流、脚本或样式。
2. 更新 `TEMPLATE_VERSION`，使用可排序且不可复用的版本字符串。
3. 在干净的新用户 workspace 跑六条真实命令。
4. 对一个专门升级测试用户制造“未修改文件、已修改受管文件、个人数据”三种情况。
5. 确认只更新第一类、第二类报告冲突、第三类保持不变。
6. 部署代码后，由管理员逐用户升级，不做批量静默升级。
